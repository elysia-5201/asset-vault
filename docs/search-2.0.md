# AssetVault Search 2.0 交付与验收

## 结论

搜索主链、增量索引和界面已实现。正式库只用于只读取样，迁移、修改、重建和安装验证均在隔离环境完成。正式桌面版仍是原版本。该验收记录来自改造时的集成环境。公开分支单独复验了搜索主链和数据库迁移。

十万条场景下，热缓存与测试维度的筛选计数达标。冷连接、无缓存宽查询和重建并发时仍有超时延目标的样本。真实图形窗口和滚轮帧时间没有完成验收。本地 AI 阶段保留接口，等待普通搜索通过性能与桌面门槛。

## 1. 现状审计与失败根因

| 环节 | 原有行为 | 实际影响 |
| --- | --- | --- |
| 请求与状态 | 搜索输入 250 ms 防抖，主列表有序号防旧响应覆盖，只有分类计数取消网络请求，@语法在前端解析 | 新输入无法取消旧列表请求，@和筛选器使用两处语义 |
| 文本召回 | 单一完整 FTS5 trigram 短语，字段为标题、店铺、作者、描述、备注和标签 | 组合词、商品号、全角输入、跨语言和包路径经常没有结果 |
| 短词 | 少于三字符时通过 LIKE 搜索商品表与关联标签 | 执行计划出现全表扫描，短词分支还漏掉了描述 |
| 排序与分页 | 推荐顺序实为更新时间，分页已有唯一 ID 兜底 | 精确商品或主要用途无法升到首位，原有稳定兜底可以复用 |
| 索引维护 | Repo 写入商品及标签时同步旧 FTS，包内容已存在关系表 | 库内旧 FTS 有记录，但文件名和包内路径不参与它的搜索 |
| 渲染 | 分页累加卡片，图片懒加载，CSS 延迟部分布局 | 已加载卡片仍留在 DOM，本次改为行窗口 |

正式库只读基线取得 56 条商品记录、41 条非回收站商品、58 条文件、56 条旧 FTS 记录。共有 478 条归档目录和 165 条 UnityPackage 资源路径。旧 FTS 对三字以上的查询使用虚拟表索引与项目主键查找，排序使用临时 B-tree。旧短词查询的计划为商品表扫描、关联标签主键查找。

## 2. 搜索主链

沿用列表接口和原有资料模型。输入先标准化并生成查询 AST，语法与自然条件再合流。召回使用商品号、完整名称与路径、全文、Avatar 证据、主体分类、短词、文件路径及近似拼写。硬条件筛选、去重和稳定排序后，才载入一页卡片的数据。结果粒度默认是商品，文件和包内路径作为命中证据展示。组合自然查询里的颜色和风格作为辅助排序项，使用显式字段时才成为硬条件。

搜索读取使用独立的只读 SQLite 线程，索引写入使用另一个限预算线程。前端 180 ms 输入防抖、取消旧请求并保留响应序号防串台。关闭连接可以移除仍在队列中的搜索。已经执行的 SQLite 查询结束后释放线程。连续相同查询使用有界缓存，同库写入、其他连接提交及时间窗口变化时会失效。

## 4. 数据库迁移与数据保护

搜索派生表使用 schema 14。公开主分支此前为 schema 10，本改动只应用搜索索引所需的附加结构。给派生搜索数据增加 `search_documents`、`search_text_fts`、`search_terms_fts`、`search_dirty` 和 `search_lexicon`。新增查询用索引和变更触发器。保留 `items_fts` 作为旧库补索引时的文本来源。现存人工标签、手动或已确认分类和手动 Avatar 行在真实库副本迁移前后逐行相同，`quick_check` 和外键检查通过。

## 5. HTTP API 与兼容性

| 接口 | 行为 |
| --- | --- |
| `GET /api/items` | 保持 `total/items` 和原有筛选参数，增加相关度排序、搜索条件和命中理由，`debug=1` 可看每个词的贡献及召回通道 |
| `GET /api/categories/counts` | 共享 AST 和候选逻辑，分类计数参考其它维度 |
| `GET /api/search/suggestions` | Avatar、分类、词库、标题及近似拼写建议 |
| `GET /api/search/facets` | 按维度聚合结果数量，每维至多返回 30 项 |
| `GET /api/search/alternatives` | 明示移除一个条件后有多少匹配，保留明确的 Avatar 条件 |
| `GET/POST /api/search/index` | 索引版本和进度、增量修复、重建、暂停、继续及取消重建 |
| `GET /api/search/lexicon` 与 `PUT/DELETE /api/search/lexicon/:id` | 查询和更新自定义词项 |

整理待办复用统一搜索解析和过滤，保留待办原有范围与排序。精确文件路径使用已有规范路径索引。带引号的词可以作为完整短语，支持转义引号和空格。未知字段、缺值、非法大小或日期、未闭合引号会返回可读的 400 错误。

## 6. 词库与标准化

内置词库使用独立版本号，每个概念包含稳定 ID、显示名、多语词形、可选主体类别和低权重关联词。支持 NFKC、大小写、宽窄字符、平片假名、驼峰名与文件分隔符。读取数据库里已有的 Avatar 名称及别名，常见中文名补充过滤候选，用户自定义别名优先。

词库改动重新解释查询，实物索引记录原词和标准化词，词库更新无需全库读取。主体分类的父子关系使用现有体系。连衣裙与半身裙可互相召回，但只有主体类别符合时才满足硬分类条件。未识别词继续参与文本召回。

## 7. 相关度与解释

精确商品号通过来源索引限定。完整标题权重最高，明确输入完整多词标题时优先返回同名条目。通常每个查询词只采用最强来源的分值，多个词提高覆盖度。确认适配、可能适配、主体分类、用户标签、标题、作者、文件名、说明、包内路径和近似拼写采用同一分值尺度。严格同义词约为直接命中的 76%，关联词约为 43%。收藏只作为同分时的辅助顺序，唯一 ID 是最后的稳定排序键。

显式 Avatar 排除保留。包内存在文件可提供命中证据，主体分类仍来自商品分类数据。单一召回通道最多处理 12,000 条候选，宽泛结果统计可能受上限影响。当前排序按固定数据快照验证了无重复和遗漏，浏览期间库发生写入时仍使用现有 offset 分页契约。

## 8. 深度内容和索引生命周期

搜索只读取已解析的归档路径、UnityPackage 资源路径与素材单元。路径、格式和 Shader 条件可以查询这些数据，返回证据区分原始素材文件、归档内文件、UnityPackage 内文件以及库里已经登记的依赖。尚未有证据的引用不会标为已验证依赖。

待写队列通过 SQLite 事务和触发器保护。商品元数据、标签、附件归属、路径和解析产物发生变化时仅更新受影响的商品。分类、明确的适配、来源和版本相关过滤查询主表。索引重建分批更换派生记录，旧的正常记录在处理完成前可继续使用。维护入口复用现有 `reindex` 作业及其租约 fencing 来排队，索引线程持久化并消费队列。失败可修复，重启续接待处理记录。普通路径索引的每个来源上限为 2,500 条路径，每个路径字段上限为 512,000 字符。未解包、部分解包和路径受限分别显示。

## 9. 准确率对照

取 41 条在库商品的只读副本。在两版都运行并已标注目标的 10 条查询中，相关商品共 12 件。旧版在 Top 20 找到 2 件，新版找到 12 件。这个小样本用于确认已复现的问题有改善，不能推定整体跨语言 Recall@20 或 Precision@10 已达标。

| 样例 | 旧版 | 新版 |
| --- | --- | --- |
| 样本商品 商品号 | 0 条 | Top 1 |
| 样本商品 完整标题 | Top 1 | Top 1 |
| 全角 样本商品 和少一字符的拼写 | 0 条 | 各自 Top 1 |
| 抚摸音效插件 | 0 条 | 3 件已核对相关商品 |
| 玛努卡 妆容 | 0 条 | 正确目标 Top 1，另有一个描述匹配 |
| 日文商品名称片段 | 目标 Top 1 | 仍为 Top 1，另有两个扩展匹配 |
| 样本商品 ZIP 文件名 | 0 条 | Top 1 |
| 组合 Avatar、商品号、文件大小条件 | 0 条 | 两条对照查询均为 Top 1 |
| PSD 和 FBX 包内文件 | 原字段未覆盖 | 在实际解析数据中分别命中正确商品 |

副本重建后 41 条商品索引完成，仍有 26 个在库素材文件未完整解析、3 个文件在上游处理时受限。更完整的人工标注库需要包含长尾类别、误召回、同名商品和歧义 Avatar。

## 10. 性能基准

Windows 11 22631，Ryzen 7 9800X3D，测试进程可见 8 个逻辑 CPU 与约 23.61 GiB 内存，Node v24.19.0，SQLite 3.53.4。每个商品有 1 个资产及 3 条归档路径。库为本地磁盘隔离 SQLite，测量 SQL、候选合并与卡片组装。冷指新 SQLite 连接，未清空操作系统磁盘缓存。下表是 7 个样例各自的 P95 中最大值。每查询 24 次热缓存、6 次冷连接、12 次无响应缓存、12 次后台并发。筛选为一次 Avatar 维度聚合，共 16 次。

| 商品 / 包内路径 | 热缓存 ms | 冷连接 ms | 无响应缓存 ms | 重建并发 ms | 筛选 ms | 索引构建 | 搜索索引 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 10,000 / 30,000 | 0.067 | 21.49 | 17.24 | 15.21 | 9.44 | 2.62 s | 20.2 MiB |
| 50,000 / 150,000 | 0.081 | 71.30 | 70.70 | 74.19 | 32.70 | 10.69 s | 100.6 MiB |
| 100,000 / 300,000 | 0.094 | 237.06 | 137.99 | 213.07 | 93.19 | 22.87 s | 201.1 MiB |

十万条库文件约 298.9 MiB，基准进程 RSS 约 155.5 MiB，构建约 4,373 条/秒。每档热样本中 161/168 次命中响应缓存。原始记录含 P50/P95/P99、RSS、CPU 时间、文件大小、缓存命中与重建进度。十万条冷连接的商品号、完整标题与具体包内文件分别为 4.36、3.22、5.22 ms。拖慢冷查询的是高频两字词和全库包内格式通配符。并发热点为宽泛的文本检索。部分旧版基线查询因旧功能不支持而返回零条，它们的时间不能直接当作等价结果上的性能改善。

## 11. 自动化测试

此前集成环境完整测试 1,479 项，1,439 通过、0 失败、40 条环境相关跳过。类型检查与补丁检查通过。专项覆盖 AST、跨语检索、负条件、路径和格式、人工属性保护、稳定分页、统计、逐词评分、无结果放宽、迁移、增量更新、重建期间可读和取消作业。真实库副本额外通过数据库完整性与关联检查。

以公开主分支为基线再次验证。搜索与迁移相关的 43 项专项测试全部通过，类型检查和前端构建也通过。全仓对照为基线 1,315 通过、30 失败、28 跳过，加入本次改动后为 1,317 通过、30 失败、28 跳过。两次的失败用例相同，包含 Windows 符号链接、进程退出行为及原有工作流断言。

## 12. 桌面验收

用复制的 Windows 便携包完成隔离安装和文件 SHA-256 核对。通过同一 Electron 38.8.6 的 Node 模式连接安装后的程序和原生 SQLite 模块，验证后台两线程、商品号与中日跨语言检索、索引和 Web 入口。标准窗口验收受测试环境限制。原生控制连接不可用，隔离 Chromium GPU 子进程报 DLL 未找到并退出，Chrome 和 Edge 的 CDP 页面操作也未响应。因此没有实际生成前端渲染、滚轮帧时间或长任务数据，页面流畅性仍待真实 Windows 会话验收。

## 13. 未通过或待补齐

- 十万条冷查询、无缓存宽查询和重建并发的最慢样例仍超过 100 ms。
- 尚未完成真实桌面滚轮、键盘导航、列表视图的图形系统验收。自动化界面测量脚本可在可用 Chromium 环境运行。
- 动态筛选覆盖 Avatar、一级和二级分类、作者、标签、颜色、风格、来源、状态、文件格式、大小、可用性、入库和更新时间、收藏、Unity 导入以及待更新状态。颜色和风格计数依赖已有标签，包内格式计数依赖已解析路径。搜索收藏会保存文字和内嵌的高级筛选表达式。
- 未知或尚未建立的 Shader 引用不在已验证依赖集合内。零结果时可查看分条件放宽数量、词汇和拼写建议。独立的相关商品推荐还未接入。
- 本地 AI 和以图搜图尚未启用。已提供 `LocalSearchProvider` 类型契约，包含本地模型版本、可查询范围、上限和取消信号。没有生成模拟向量或模型分数。

## 14. 构建与隔离安装

构建 Windows 桌面版可运行 `npm run desktop:dist`。公开仓库提供源码与回归测试。集成环境的 Electron 隔离安装验证见第 12 节。

## 15. 维护与扩展

优先优化宽泛短词和格式集合的求交与分页，再复测冷连接、后台重建及真实桌面滚动。扩充人工标注时保留现有困难样例，分开计算精确、扩展和深度查询的结果。普通搜索完成验收后，再以独立本地进程接入模型，并将向量结果与既有硬筛选范围求交。
