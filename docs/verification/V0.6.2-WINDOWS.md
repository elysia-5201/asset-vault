### 2.3 FIX-07：测试内的 POSIX `cp` 平台假设（Gate 0.5 发现）
Windows 首跑失败 2 例，均为 `test/pipeline/cache-identity.test.ts` 用 `execFileSync("cp", ["-p", ...])` 制造“同 inode/size/mtime、内容被换”的样本：
- `① 就地覆盖（同 inode/size/mtime）→ 采样变 → MISS`：`spawnSync cp ENOENT`。
- `⑤ 陈旧 sha + 同 size+mtime 替换…`：同上。

修复（不改断言、不降语义）：新增 `overwriteInPlace(src, dst)` —— 读源文件后对目标 `open r+ → ftruncate(0) → write`，再回填源 mtime；在 POSIX 上保持 inode 不变，Windows 上等价“就地改内容”。两处调用替换；标题去掉了 “GNU cp -p”。文件 md5 `4e0cf7f687bc553ab462e89798a458e7`（原 `adecf69` 版本 `…` 未单独记录）。单独跑该文件 24/24 pass；全量 Windows 691/668/0/23/0。

> 这是测试可移植性修复，不影响产品代码；但说明 v0.6.2 新增的 AUD-03 回归测试只在 POSIX 上验证过。

## 9. 偏差、修补与工具链发现

1. **FIX-07（测试可移植性）**：见 §2.3；Test-only，未改产品。
2. **部署 /MIR 删除回滚目录**：目标端旧 `win-deploy.cmd` 未排除 `rollback-v0.6.1`，同步时删除了刚建的快照；已改源码排除项（`scripts/win-deploy.cmd` md5 `6186e76cd0e991fb05f5f247716f9298`），并用 `b77ea2f` 重建 `rollback-v0.6.1`（2,873,568 B）。重建的 0.6.1 脚本为 LF（当时未修），因此 `check-windows-scripts.mjs` 增加跳过 `rollback-*`（md5 `34ce3d32050d34286bf94402378b1432`）。
3. **停止脚本不清理锁**：`stop-assetvault.cmd` 强制结束进程后留下 `pipeline.lock`；本次按 lock 内 pid 判死清理。建议 stop 脚本增加清理（低风险，未改）。
4. **CLI 无优雅关闭端点**：迁移/验收用强制结束；每次均校验 pid 死亡后删锁，并用 checkpoint 验证。
5. **Ctrl+zoom 未实现**：确认无变化，按已知限制记录（不阻塞）。
6. **IME 仅模拟**：CDP 合成输入验证了前端接收链路，真实输入法组合/提交仍为 UNVERIFIED。
