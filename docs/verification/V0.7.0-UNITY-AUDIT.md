## 4. 现有导入链路（代码审计）

| 环节 | 位置 | 行为 |
|---|---|---|
| 端点选择 | `apps/server/src/services/unity.ts:19, 123`；`routes.ts:230-234` | `settings.unity_mcp_url` 优先，否则依次 `8080/mcp`、`14523/mcp`；无 TLS/鉴权 |
| 握手 | `unity.ts:157-176` | `initialize`（protocolVersion `2025-06-18`，clientInfo asset-vault 0.1.0）→ `notifications/initialized`，要求返回 `mcp-session-id` |
| 执行 C# | `unity.ts:202-211` | `tools/call execute_code {action:"execute", safety_checks:true}`；返回 structuredContent.data.result |
| 列包 | `unity.ts:258-338`；`routes.ts:1183-1198` | 直接 `.unitypackage` + zip/7z/rar 内层包 + zip 套 zip（≤16 层，内层 ≤512 MB）；按 avatar 名匹配排序 |
| 暂存 | `unity.ts:341-361` | 压缩包内的包解到 `<dataDir>/unity-staging/<assetId>/<label 清洗后>`；label 清洗 `[^\w.\-\u4e00-\u9fff] → _` |
| 导入 | `unity.ts:364-384` | 把路径拼成 C# `string[]`（只转义 `"`），逐包 `AssetDatabase.ImportPackage(path, false)`（**interactive=false**） |
| 结果 | `routes.ts:1221-1247` | 先清控制台 → 暂存 → 导入 → **sleep 1800 ms** → 读 error 控制台；返回 queued/failed/consoleErrors；`project_imports` 在导入**排队后**就写入 |
| 自动选择 | `routes.ts:1213-1215` | 未指定 keys 时：优先只导“当前工程 avatar 匹配”的包，否则**全部**，最多 20 个包；**无总字节上限** |

## 5. 风险清单（只读审计结论）

| # | 风险 | 证据 | 影响 |
|---|---|---|---|
| R1 | **导入不可交互且会编译/执行包内脚本** | `AssetDatabase.ImportPackage(path,false)`（unity.ts:372）；PCSS 10 个 .cs、FadeOut 2 个 Editor .cs | 不可信 .unitypackage 可在编辑器内触发 InitializeOnLoad/AssetPostprocessor 等代码执行，导入前无内容审查确认 |
| R2 | **本机 MCP 无鉴权但可执行任意 C#** | 127.0.0.1:8080 明文 HTTP；`execute_code` 已启用（EditorPrefs=1）；任何本机进程均可调用 | 本地提权/横向：能访问该端口的进程可驱动编辑器执行代码；`settings.unity_mcp_url` 可被改成远程地址（SSRF/代码执行面） |
| R3 | **MCP 依赖浮动 `#main`、版本漂移** | manifest 全用 `#main`；lock 无 commit；三工程 9.6.8/10.1.2/10.2.0 | 供应链更新不可复现；不同工程协议/工具行为不一致 |
| R4 | **staging 无回收** | 23 包 / 793.6 MB 已存在；代码只写不删 | 反复导入会持续膨胀（与生产数据同盘） |
| R5 | **导入结果不可证实** | 只 sleep 1.8 s 读一次 console error；记录在 QUEUED 后即写 | 大包/慢编译时错误漏报；`project_imports` 可能记录“已导入”但实际失败 |
| R6 | **自动全导无总量上限** | 无 keys 且无 avatar 匹配时导全部，`slice(0,20)`；单包上限 2 GB | 可能一次导入数十 GB/大量脚本；磁盘与编译时间不可控 |
| R7 | **当前离线不可用** | 8080/14523 closed、无 Unity 进程 | 详情页“导入到 Unity”会 503；需先开 Editor+MCP Server |
| R8 | **Moe 工程未装 MCP** | Moe manifest 无 com.coplaydev.unity-mcp | 在 Moe 中打开时无法探测/导入 |
| R9 | **列表截断** | `DEFAULT_MAX_ASSETS=10000`（core/unitypackage.ts）；超限 limited | 超大包（>1 万 GUID）列表不完整，会影响“选择哪些包”界面 |
| R10 | **无包完整性校验** | 导入前不校验 sha256/签名；包来自本地下载目录 | 文件被替换/损坏时仍会导入；与生产文件身份（sha）未绑定 |

## 6. 建议（未实施，供 v0.7.0 设计）

1. 导入前显式确认：展示包内 `.cs/.dll`、Editor 目录、总大小；对含脚本或未知来源的包默认 `interactive=true` 或拒绝，至少要求二次确认。
2. 导入前对源文件做 sha256 并在导入后核对 `project_imports`，并以“控制台无 error + 目标路径存在”判定成功，而不是 1.8 s 后读一次。
3. staging 增加 LRU/按大小回收（或在导入成功后删除临时副本；直接文件无需暂存）。
4. 对“无 keys 自动全导”加总字节/包数上限；默认只导 matched，全导需显式请求。
5. 固定 MCP 版本（commit hash）；启动时校验 `serverInfo.version` 与协议；Moe 工程补装。
6. `unity_mcp_url` 仅允许 loopback/显式白名单；考虑给 MCP 端点加 token（若上游支持）。
7. 在 UI 上把“离线/未装 MCP/版本不符”分开提示（当前统一 UPSTREAM_ERROR）。
