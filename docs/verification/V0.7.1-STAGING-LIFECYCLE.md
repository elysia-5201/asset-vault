## 2. 实现（v9，已部署）

- 台账：`staging_files`（path_norm/size/plan_id/run_id/job_id/state/created_at/last_used_at/cleanup_error/attempts）。
- 写入：`stageUnitPackage`（structure，`unit-*`）与 `stageUnityPackage`（`<assetId>/<label>`）写入后登记。
- 运行级清理：`cleanupStagingForRun` 在 run `verified/partial_success` 后删除该 run 的文件；失败/unknown 保留。
- 过期清理：`sweepStaging` 删除 `last_used_at < now-7d` 且非活跃 run 的**已登记**行；路径必须在 stagingDir 内、拒符号链接、支持 dry-run。
- 启动：`sweepStagingOnStartup`（7 天）**并收养未登记文件**（本次 23 个 → stale 行）。
- API：`GET /api/staging`、`POST /api/staging/cleanup`（dryRun）。
- 生产只读核对：schema v9、`staging_files` 12 行、SUM(size)=742,457,798、state 全 `stale`。

## 3. 剩余风险

1. 剩余 12 个（709 MiB）在 7 天窗口内仍占盘；属预期（未到期的 stale）。
2. 同名覆盖路径语义仍在（`<assetId>/<label>`）；台账缓解但不改路径。
3. 列表/详情路径（`routes.ts` 的 asset unitypackage 预览）也会写 staging；需确认都登记，避免产生新的未登记文件。
4. 备份/部署仍不含 staging（派生数据；win-backup 只备份 DB，win-deploy 排除 data）。

## 4. 建议

- 观察下次启动/7 天后 sweep 是否清掉剩余 12 个；若仍在，检查 last_used_at 与 active-run 判定。
- UI 增加存储与清理入口（API 已有）；对“立即清理”保留 dry-run 预览。
- 列表/详情 staging 若只读展示，优先走临时目录，避免污染 data/unity-staging。
