## 2. 差距（本任务要补）

1. **没有资源单元（Asset Unit）模型**：外层 zip 内的独立 .unitypackage 只存在于候选扫描结果里，不能持久化、筛选、复用。
2. **没有结构策略**：无法判定 multi_package_container / mixed_unitypackage / single / unknown；也没有“混合包必须整包导入”的硬约束落点。
3. **没有包内 Avatar 证据分级**：matchAvatarByText 只给一个 hint；不区分商品声明、文件名、包内路径、人工确认，也不记录冲突。
4. **没有资源关系**：模型包/材质包/贴图包只能靠文件名猜；无关系表、无证据、无确认位。
5. **没有导入计划/执行记录**：`/api/unity/import` 一次调用返回 queued/failed + 控制台错误；无 plan、无 precheck、无逐单元状态、无指纹校验、无中断恢复语义。
6. **没有工作台**：无法按 Avatar 浏览候选、看证据、组清单、生成计划。
7. **混合包保护未实现**：现在没有代码会拆包（因为根本不解析内部 avatar），但也没有“禁止拆包”的显式策略与测试。
8. **验证缺失**：导入调用返回即认为完成；未检查工程中是否真的出现资源 GUID。

## 3. 最小改动方案

- 新增 schema v8：`asset_units`、`unit_relations`、`import_plans`、`import_plan_items`、`import_runs`、`import_run_items`；不复制 items/assets/avatars。
- 新增 `packages/core/src/structure.ts` 纯函数：证据提取、policy 判定、关系候选。
- 新增 `apps/server/src/services/structure.ts`：按 item 分析容器→单元→证据→关系，幂等 upsert；job kind `structure`。
- 新 API：`/api/workbench/*`、`/api/import-plans/*`、`/api/import-runs/*`；复用 `services/unity.ts` 的 stage/import/console。
- 新 UI：AvatarWorkbench 面板（工具栏入口），复用现有卡片/筛选/状态样式。
- 测试：core 纯函数、结构与计划（合成 zip/upkg）、执行状态（无 Unity 时走 unknown/failed，不伪造 verified）。

## 4. 明确不做 / 边界

- 不自动穿戴、不绑骨骼、不配置材质；本期只到“资源导入 + 可验证结果”。
- 不修改原始 zip/unitypackage；不生成筛选版 mixed 包。
- 不保证解析所有格式：7z/rar 内嵌图、加密包、损坏包按 limited/failed/unknown 记录。
- 真实 Unity 导入验证依赖本机 Editor 与 mcp-for-unity；不可用则标 UNVERIFIED。
