## 3. core 结构识别（A/B/C/D/E）

`packages/core/src/structure.ts`（纯函数，无 DB/IO）：

- **evidence**：`detectUnitAvatars(texts, avatars, itemAvatarIds)` — 别名/大小写/全半角（NFKC）/假名折叠；同 avatar 合并 hits；item_avatar=confirmed、filename/package_path=probable；`hits` 记录原文。
- **policy**：`decidePolicy({container,kind,innerUnitypackagePaths,mixedAvatarCount,parseState,mixedConfirmed})` — kind=unitypackage → mixed（≥2 模型证据或显式确认）否则 single；archive 内 >1 upkg → multi；=1 → 按该包 mixed 判定；解析失败/无 upkg → unknown。外层 ZIP **不构成** mixed。
- **relations**：`relationCandidates(units)` — 同 avatar 同名变体 → optional_variant；去伴生后缀后同 stem → suggested_companion；均 probable，**永不 confirmed**；跨 avatar 不产出。
- **A/B/C/D/E 验收**（`scripts/acceptance-structure.mjs`，真实 zip/tar.gz 夹具）：
  - A 外层 zip 2+ 独立 upkg + pdf → multi_package_container，3 个单元各自可选（可独立解析）。
  - B 单 upkg 混合 2 Avatar → mixed，单文件不可拆。
  - C zip 内只含混合包 → mixed（不是 multi，不得拆）。
  - D 模型/材质/贴图三 upkg → suggested_companion ×3/probable，无 confirmed、跨 avatar 不误配。
  - E1 损坏 zip → NOT_AN_ARCHIVE；E2 截断 upkg → NOT_AN_ARCHIVE；E3 超限 → limited ENTRIES/BYTES；E4 zip-slip 目录层剔除 + 读取越界 NOT_FOUND；E5 depth 边界见 §5；E6 文件被改 → sha 变化 + 再解析失败。
  - G-1 全部夹具解析前后 sha256/mtime 不变（解析只读）。

## 5. 疯狂边界（任务 45：真实 190MB 包）

- 嵌套发现预算：**depth=3**、**archives=32**、**累计字节 512MB**、时间预算 **45s**、内层条目 5000。
- 内层 upkg 内容解析预算：每项 ≤64 包、累计 512MB、45s、最多 1 万资产条目；读不到/超限 → 标 limited，不伪造成功。
- 验收：depth=3 展开出 `outer::inner::pkg` 可导入单元并可建计划；**depth=4** 只产出 limited 单元（不可导入、建计划 INVALID_INPUT）。
- 真实 190MB 包（item 6 的 175MB + 15MB zip）在 depth=3 下 36 单元/32 可导入，errors=0。

## 7. 计划 precheck（mixed 语义）

- mixed 单元：`import_plan_items.path = 原始容器路径`（如 `...\B_mixed.unitypackage`），`rel_path` 指向包内条目（嵌套为 `outer::inner::pkg`）；**绝不生成筛选/拆分包**，计划阶段不落地暂存产物。
- 状态：mixed 或含 suggested → `needs_confirmation`；指纹/文件变化 → `blocked`（precheck 抛 `FINGERPRINT_CHANGED`）。
- 计划内容：仅选中单元；`includeSuggested=true` 才加入关系建议（标 suggested，确认后转 pending）。
- 验收：B-1b/1c/1d/1e、B-2b..2d（含目录零新增）、B-3b/3c 全 PASS。

## 8. 执行 Job 202 与失败审计

- `POST /api/import-plans/:id/execute` 仅做 precheck + 创建 job，返回 **202 `{jobId, planId}`**；重复执行 409；job kind=`import`、payload=`{planId}`；执行状态由 Job runner 驱动。
- 逐单元 run_items：importing → import_command_completed → verifying → verified/partial_success/failed（命令完成 ≠ 验证成功；GUID/console 验证仅 Unity 可用时）。
- **前置失败审计（task-46）**：precheck/Unity 离线/工程不匹配等失败 → 也创建 **failed run + 每个 plan_item 一条 failed run_item**（detail.phase=preflight）+ `import_runs.summary = {phase:"preflight", error, total, failed}` + `plan.status=failed`；`GET /api/import-plans/:id` 的 `lastError.code` 可读（如 `UNITY_UNAVAILABLE`）。
- 验收：B-4a（UNITY_UNAVAILABLE）/B-4b（源文件 sha256 不变）/B-4c（run.status=failed、phase=preflight）/B-4d（逐项 failed run_item）/B-4e（lastError.code）全 PASS。
- 真实 Windows 证据：`logs\server.log` 中 `job 29/30 failed: 连不上 Unity MCP（127.0.0.1:8080/14523 fetch failed）` —— 失败审计按上述结构落盘。
