# AssetVault v0.6.0 实施与验证报告

> 日期：2026-10-20 · 基线：v0.5.1（`c366aa8`）· 改造：后台索引流水线 / 超大压缩包 / 派生缓存
> 设计说明：[`docs/pipeline-v06.md`](../pipeline-v06.md) · 接口契约：[`docs/api.md`](../api.md)

---

## 1. 交付范围

| 目标 | 实现 |
|---|---|
| 发现 → 建档 → 深度解析解耦 | `jobs` 只入队 + 有界等待；`index_tasks` 承载 7 类阶段 |
| 单个大包不阻塞队列 | 每阶段独立并发上限；大包 hash/archive 与其它资产并行；作业默认最多等 8s |
| 分块哈希 / 文件身份 | 流式 sha256（1MiB 块、可取消、带进度）；超过上限标 limited |
| 压缩包资源限制 | 大小/条目/单条目/累计读取/嵌套层数/压缩比/超时全部可配 |
| 独立缩略图流水线 | 独立队列、像素上限、失败保留旧封面、异步原子写 |
| 统一缓存 | 目录 / unitypackage 列表按「内容身份 + 解析器版本 + 限制指纹」缓存；LRU+过期+原子写 |
| 进度 / 取消 / 恢复 / 诊断 | 任务进度节流落库、协作取消、崩溃恢复、`pipeline_events`、面板 |
| 安全 | 归档路径校验、超限降级、临时文件受控清理、不删除素材 |

**不做**：技术栈替换、全库重写、第二套作业状态机、自动删除/合并用户素材。

## 7. 基准（同一机器、同一数据集、冷缓存）

环境：WSL2 Linux x64 / Node v22.22.0 / 8 vCPU / 本地磁盘；夹具由脚本生成（1000 个内容相同的
小 zip + 1 个混合包 + 1 个 100MB zip + 1 个 unitypackage），冷缓存（每轮新临时库与缓存目录）。

| 指标 | 流水线（本轮） | 0.5.1 串行内联（`--legacy`，同数据集） |
|---|---|---|
| 资产数 / 总体积 | 1004 / 105 MB | 见 §7.2（500 / 0.2 MB） |
| 文件发现 | 10 ms（98,228 files/s） | 同（发现逻辑未变） |
| 基础建档 | 446 ms（2,250 assets/s） | 同 |
| 深度索引 | 10.6 s（全部任务 settle） | §7.2 |
| 峰值 RSS | 482 MB | §7.2 |
| 事件循环 p95 / max | 5 ms / 1266 ms（单次尖峰） | §7.2 |
| 缓存命中率（第二轮） | 99.0% | 无缓存系统 |

> 事件循环尖峰：JS heap 仅 21MB 而 RSS 390MB → 原生侧（sharp/SQLite）单次停顿，非 JS 长任务。
> 大文件单独解析（100MB zip）实测 max 2ms、峰值 RSS 163MB（`--small=0 --big-mb=100`）。

### 7.2 前后对比（500 个相同小文件，同一机器/同一夹具）

| 指标 | v0.6.0 流水线 | v0.5.1 串行内联（同链路：索引→匹配→分类→FTS） |
|---|---|---|
| 深度索引总耗时 | 5.82 s | 3.71 s |
| 峰值 RSS | 319 MB | 270 MB |
| 事件循环 p95 / max | 6 ms / 626 ms | 3 ms / 220 ms |
| 任务账本 | 3,023 行 index_tasks | 无 |

**结论**：纯小文件吞吐上流水线慢约 1.57×，成本来自 6 条阶段任务与按阶段的数据库往返；
收益是大包隔离、资源有上限、可取消/可恢复/可诊断。不把"更慢"包装成"更快"。
该开销可通过"小文件多阶段合并批任务"优化，但会牺牲部分隔离性，留作下一轮。

### 7.3 大包隔离（结构性验证）

`--small=0 --big-mb=100`：100MB zip 的 hash+目录+缩略图在 156ms 内完成，max lag 2ms、峰值 RSS 163MB；
`--small=1000 --big-mb=100` 时小文件仍按各自阶段完成，大包只占用 1 个 archive/hash 槽。
这是流水线相对 0.5.1"一个作业串行索引全部资产"的核心差异。

## 9. 已知限制与后续

1. 1000 资产批量索引时出现单次 ~0.8–1.3s 原生停顿（p95 5–7ms）；根因指向 sharp/SQLite 原生调用，
   彻底消除需把 SQLite 写入或图片处理移到 Worker（下一轮）。
2. 哈希与目录解析并行 → 首轮目录缓存可能是弱身份（size:mtime）；第二轮起走 sha256 键。
3. 7z/rar 内嵌图仍不抽缩略图；嵌套只展开 1 层。
4. 发现阶段仍保留全量 `filesOut`（上限 2 万）；`onBatch` 已就绪但生产未接线。
5. `jobs` 无租约/心跳；跨进程取消仍依赖单写入者锁。
6. `job_events` / `pipeline_events` 无自动保留策略。
7. Windows 原生与 Electron 运行时未在本轮验证（见 §8）。

## 10. 升级与异常恢复

1. 备份：`vault.db` + `vault.db-wal` + `vault.db-shm`（缺 WAL 会得到旧状态）。
2. 启动新版本：首次启动自动迁移到 v5；日志出现 `pipeline limits v…` 与 `pipeline disabled`（若锁被占）。
3. 若升级后索引异常：`GET /api/pipeline` 看失败与 `lastError`；`POST /api/pipeline/tasks/:id/retry`。
4. 单个包超限：调大 `PUT /api/pipeline/limits` → 重启 → `POST /api/pipeline/assets/:id/reindex`。
5. 缓存异常：`POST /api/pipeline/gc` 或停止服务后删除 `data/cache`（可重建，不碰素材）。
6. 回滚：停服务 → 换回 v0.5.1 代码 → 用备份恢复数据库（v5 表会被忽略，但建议回到备份）。
