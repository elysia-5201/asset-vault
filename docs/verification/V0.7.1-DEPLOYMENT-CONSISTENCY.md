## 5. 发现

| ID | 发现 | 影响 |
|---|---|---|
| D1 | Electron exe 元数据仍是 0.6.2（壳），payload 0.7.1；无 0.7.x electron-builder 日志/zip | 发布产物不可信/不可复现；Windows 属性/杀软/升级判断会看到 0.6.2 |
| D2 | 部署根 Web dist 是 0.6.2 旧包（`D2gA72wr`），与根 package 0.7.1 不符 | CLI/自启入口 UI 缺 0.7.x 工作台，且与后端 API 可能不匹配 |
| D3 | 部署根源码混合（unity.ts=HEAD，App.tsx=10-17，AvatarWorkbench 缺失） | CLI 走 tsx 源码时行为不可预期；与 Electron bundle 不一致 |
| D4 | 包内源码文件也是旧版本（unity.ts=10-05、schema=0.6.2），仅 built 产物较新 | 包内源码不可用于排障/二次构建 |
| D5 | 工作树未提交 v9（staging 台账 + 风险扫描）未构建进任何产物 | 部署与工作树不是同一版本（预期，但发布前需确认） |

## 6. 建议

1. 发布前在目标 commit 上重跑 `npm run build:web && npm run desktop:bundle && npm run desktop:dist`，确保 exe ProductVersion=目标版本，产出 portable zip + sha256。
2. 部署根也重新 `build:web`（或统一用完整发布包部署），保证 CLI 与 Electron 的 Web 产物一致。
3. 加一个发布一致性检查：比较根/包内 `server.mjs`、`schema.sql`、`index.html`、`assets/*.js` 与构建输出哈希；不一致则阻止发布。
4. 若 v0.7.1 不打算发版，至少修复 D1/D2（重建 Electron 0.7.1 + 根 Web），否则发布说明不能写“0.7.1 已部署一致”。
