> 基线：`b77ea2f`（v0.6.1）；工作树干净（仅 .lnk 未跟踪）。**不改阈值/夹具**，只复测与对照报告。
> 原始日志：`logs/aud05/`（env.txt、all-runs.log、{500,1000}-{pipe,legacy}-run{1,2}.log、costs-{500,1000}.log、summary.txt）。
> 命令（与报告 §8 一致）：`node --import tsx scripts/bench-pipeline.mjs --small=500 --bigMb=0 [--legacy]`、`--small=1000`、`node --import tsx scripts/bench-costs.mjs --small=500|1000`。

## 1. 基准定义（明确正反例）

- **指标**：`index.ms` = 从「入队全部资产」到 `pipeline.drain` 收敛（含 6 阶段完成）的墙钟；legacy = 同一夹具、同一 limits 下逐资产串行 `indexAsset→matchItem→applyCategoryEvidence→syncFts`。
- **冷缓存**：每次运行 bench 脚本都 `mkdtemp` 新建夹具 + 新 DB（脚本内保证）；无跨运行复用。
- **第二轮**：同一批资产再次 `enqueueAsset` 后的 `secondPass.ms`（缓存命中观察，不作为 G4 门槛）。
- **正例**：1000 规模 pipeline/legacy 比值 1.24–1.30，与报告 1.25–1.29 一致 → 可复现。
- **反例（不可作回归判据）**：500 规模单次 pipeline 3,919ms（比值 1.34×）。同规模第二次运行 3,088ms（1.07×）——**同一台机器、同一夹具、pipeline 单侧 27% 波动**，单次值不可作为回归信号；legacy 侧稳定（2,881–2,925ms）。
- **环境**：WSL2（kernel 6.18.40.1）、AMD Ryzen 7 9800X3D 8-Core、Node v22.22.0；运行期间 loadavg 1.4–1.85（8 核，存在其它会话/守护进程活动，见 env.txt/all-runs.log）。

## 2. 端到端复测（冷缓存，每次单独进程）

### 2.1 FIX-04 判定口径（500 三次中位 / 1000 ±0.05 容差）

方法：同机、同夹具、冷缓存，pipeline 与 legacy **各跑 3 次**；500 以 **3 次比值的中位数**为判定值（另列「中位耗时之比」作敏感性）；1000 以报告基准 1.25–1.29 为参照，实测按 **±0.05 容差**判定复现性（容差只用于「复现报告值」，不放宽 1.05 目标）。

| 规模 | pipeline 3 次 (ms) | legacy 3 次 (ms) | 三次比值 | 判定值（中位比值） | 报告基准 | 结论 |
|---|---|---|---|---|---|---|
| 500 | 3,059 / 3,101 / 3,024 | 3,000 / 2,833 / 2,899 | 1.020 / 1.095 / 1.043 | **1.043**（中位耗时之比 1.055） | 1.03×（门槛 ≤1.05） | **达标**（1.043 ≤1.05）；敏感性 1.055 略超 0.005，属边界 |
| 1000 | 7,229 / 7,182 / 7,094 | 5,970 / 5,812 / 5,943 | 1.211 / 1.236 / 1.194 | **1.208** | 1.25–1.29× | 与下限 1.25 差 **0.042 ≤ ±0.05** → 报告值可复现；但仍远高于 1.05 目标，**G4-1000 有据例外不变** |

环境：8C Ryzen 7 9800X3D / WSL2 / Node v22.22.0，commit `b77ea2f`；本轮 loadavg 0.37→1.9。原始日志：`logs/aud05/median-{500,1000}-{pipe,legacy}-run{1,2,3}.log`、`logs/aud05/median-summary.txt`、`logs/aud05/all-median.log`。

### 2.2 单次噪声证据（保留：说明为何必须取中位）

| 规模/模式 | run1 | run2 | 报告值 | 说明 |
|---|---|---|---|---|
| 500 pipeline | 3,919ms | 3,088ms | 3,231ms | 单次波动 **27%**（噪声极端值） |
| 500 legacy | 2,925ms | 2,881ms | 3,149ms | 稳定 |
| 500 比值 | **1.34×** | **1.07×** | **1.03×** | 单次不可作判据；3 次中位后收敛到 1.043 |
| 1000 pipeline | 7,306ms | 7,365ms | 7,623ms | 均值 7,336 |
| 1000 legacy | 5,914ms | 5,683ms | 6,119ms | 均值 5,799 |
| 1000 比值 | **1.24×** | **1.30×** | **1.25× / 1.29×** | 3 次中位后 1.208，仍在 ±0.05 容差内 |

**结论（按 FIX-04 口径）**：500 取 3 次中位后为 **1.043**（敏感性 1.055），判定 **达标/边界**，报告 1.03× 位于噪声区内但不再是单点判据；1000 稳定在 **1.19–1.24（中位 1.208）**，与报告 1.25–1.29 差 ≤0.05，**报告值可复现**；G4-1000 仍为有据例外（1.208 ≫ 1.05，关闭条件 task-21 不变）。

## 5. 偏差分析

1. **机器负载**：全程 loadavg 1.4–1.85（8 核），其它会话（含本审计/基准自身）参与调度；绝对耗时较报告 +5~−8% 属正常抖动。报告未记录当时 loadavg，无法逐项对齐。
2. **500 的 27% 单侧波动**：pipeline 首跑 3,919 vs 次跑 3,088；legacy 稳定。可能来源：①首跑 JIT/sharp/thumbnail 预热；②冷 FS 元数据（夹具刚生成）；③空 claim 唤醒抖动（claimNull 11,908 次/3,000 任务）。这不是回归（实现与报告同 commit），而是**测点噪声**；报告 1.03× 落在噪声区低端。
3. **500 fixedUs 234.5 低于报告 266.6**：同一代码、同一夹具，说明该指标也有 ±12% 抖动；因此 fixedUs ≤250 的「达标」判定应取多次运行的中位数，不宜单次定论。
4. **nullPoll 3.97/4.20 与报告 4.08/4.36 同量级**：确认「完成事件仍唤醒下游未就绪阶段」的残余空轮询仍在；与 G4-1000 有据例外/task-21（P2.5）一致。
5. **结论**：报告 G4 的 1000 数据与固定成本/内存/事件循环指标可复现；500 的 1.03× 不可作为稳定门槛复现。本轮不改阈值/夹具，报告建议改为「500 取 3 次中位数、1000 比值 ±0.05 容差」并在发布说明中保留该噪声定义。
