### 4.1 G4-1000 有据例外（lead 批准；**不得写成达标**）

- **目标**：pipeline/legacy 墙钟比 ≤ **1.05×**。
- **实测**：**1.25×**（7,623 / 6,119ms）与 **1.29×**（7,797 / 6,031ms）；FIX-04 三次冷跑中位 **1.208**（7,182/5,943ms，三次 1.211/1.236/1.194）——与报告下限差 0.042 ≤ ±0.05，报告值可复现，但仍远高于 1.05 目标。
- **根因（实测）**：per-stage 唤醒已实现（`notifyStages`，pipeline.ts:68/519），但**任务完成仍同时唤醒当前阶段 + 下游阶段**（`notifyStages([stage, ...NEXT_STAGES[stage]])`，pipeline.ts:369/379/414）；下游 worker 醒来时依赖常未就绪 → 空 claim。1000 规模下空 claim 仍 **26,131 次 / 2,563ms**（4.36/任务），fixed 成本 454µs/任务。drain 轮询与 enqueue 也会唤醒相关阶段。
- **非回归**：P1 前为 **1.44×（500）/ 1.46×（1000）**；本轮 1.03× / 1.25–1.29×，方向正确且大幅改善。
- **改进幅度**：pipeline 绝对耗时 1000 **−28%**（10,610→7,623ms）、500 **−43%**（5,646→3,231ms）；相对 legacy 的差距 1.46×→1.25–1.29×。
- **关闭条件**：task-21（v0.6.2 P2.5：唤醒收紧 + 第二轮快路径，**DEFERRED**）合并后重测；本轮报告维持例外，不写成通过。
